### Rules (all of them, so a new chat needs nothing else)

- Fully autonomous, no permission prompts (.claude/settings.local.json sets bypassPermissions; it is gitignored, recreate it from the old repo if missing: defaultMode bypassPermissions plus an allow list for Bash node/git/powershell, Agent, Edit, Write, Read, Glob, Grep, EnterWorktree). Questions to the owner only for real decisions; batch them.
- Builders: Opus subagents, one per item, each in a git worktree the lead creates itself (`git worktree add -b wt-<name> .claude/worktrees/<name> main`), never Fable as a subagent, Sonnet only for mechanical edits. Merge with `git -C <wt> diff HEAD > patch; git apply --3way patch`, run the checks, commit only the slice's files (`git add <files>`, never `commit -a`), then `git worktree remove --force` and `git branch -d` (never -D: the dcg guard prompts the owner on force deletes; builder branches have no commits, so -d works).
- Never modify T3 Code. reference/ is read-only (t3code nightly, busFred original), refreshed by the workspace task or `node scripts/references.mjs --yes`. Never run the `t3` CLI by hand; the extension's own pairing may. Never write to the owner's T3 data.
- Never push unless the owner says so for that push (still open: the owner has not yet said "push is fine"). Commit author `19733372+Fundryi@users.noreply.github.com`. No private data in commits. No privacy guard in this repo (owner decision 2026-10-13).
- Upstream stays mergeable: our code in its own files (src/host/ours/, src/webview/ours/ or a clearly named module), his files touched only where a feature must hook in. Merge with `git merge upstream/main`, never a rebase of pushed history; log every merge in docs/UPSTREAM.md.
- Windows first: a Windows failure of a build step or a test is ours to fix, smallest way, noted here.
- Keep it small. ASCII only in repo text we write, no em dashes, no curly quotes. Replies to the owner in the ELI5 style (short sentences, plain words). Times in STATUS from `date +%H:%M`, not guessed.
- Codex is not a gate (decision 13): adversarial or advisory questions only.
- Testing: real checks over test code. His checks: `pnpm run build`, `pnpm run typecheck`, `pnpm test`, his verify scripts in docs/development.md (isolated T3 home). A passing test is not done; check the real result. Live tests the owner must do by hand are handed over one at a time, never as a long list.
