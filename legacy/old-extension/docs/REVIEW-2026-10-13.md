# Full code review: simplification and hardening, 2026-10-13

Method: reviewed the requested production files, check scripts and design/status documents against main at 2f6c6c9 (HEAD d223feb changes only STATUS and FEATURES), the read-only T3 .3066 source and all 177 source-backed facts; Node selfchecks passed (selfcheck 98, MCP 64, panel 64, extension 106), as did focused in-memory HTTP/VM probes and live GET checks with bearer invalid; initial Bun runs failed for selfcheck, MCP (timeout) and extension, and initial rg/keyboard-extraction probes failed, all corrected and rerun; livecheck was read but not run because it creates a fixture commit, and paired WebSocket responses and real keyboard/drag interactions were not exercised.

## 1. Security boundaries (3 findings)

- **High, M - `extension.js:565` (also `t3.js:295`):** The approval toast drops provider options/warnings, truncates the command to 200 characters, and can offer Approve using only a reason when the command item is missing. A command tail or provider-supplied prompt-injection warning is invisible at the point that grants permission, and a decision the provider never offered can still be sent. Return the request's options and full relevant text from t3.js, show them before acceptance, and offer only decisions that the request supports, falling back to Show when the approval context is incomplete.

- **Medium, S - `extension.js:1058`:** Adding or removing a secondary workspace folder leaves `bind.folders` unchanged because the listener refreshes only when the first folder changes. Polls can continue listing and offering approvals for a project that no longer belongs to this window, which a two-folder removal probe reproduced. Update the bound folder list and fetch fresh activity on every workspace-folder change, using a full refresh only when the first folder changes.

- **Medium, S - `context.js:359`:** `cwdFolder(cwd)` takes precedence over `X-T3-Fallback`, so a tie between two windows on the same folder returns `match: cwd` without a warning. The agent receives another window's selection or terminal context as though routing had been unambiguous, violating decision 10's explicit disclosure requirement. Give the authenticated bridge's fallback flag precedence over the cwd match and retain the fallback note for ties.

## 2. Correctness bugs (12 findings)

- **High, M - `extension.js:391` (also `extension.js:425`, `extension.js:1014`, `t3.js:269`):** `root()` knows worktrees but falls back to the bound project's root for nested projects, while prompt references and terminal creation always use `bind.root` even for worktree threads. Selecting another related checkout can attach its main-checkout relative filename to the worktree's different file or prepare a command in the wrong repository, both reproduced with invented paths. Have t3.js return each thread's effective root, use it for file resolution, mentions and terminal cwd, and reuse a terminal only for the same root.

- **High, M - `extension.js:370`:** Navigation within one B32 frame updates the shared `current` thread without navigating the other frame. A probe left the side view on one worktree while its relative file click opened the other worktree's file, and later commands also target the shared thread rather than the page being read. Synchronize accepted thread navigation to the other page with an equality guard, and associate incoming file/actions with the sending page's confirmed thread until synchronization completes.

- **High, M - `extension.js:175` (also `t3.js:738`):** Save on send posts an asynchronous host message but lets T3's original send handler continue immediately, and `saveAll(false)` returning false is still logged as a successful save. An agent can read the old disk contents before saving finishes or after a save refusal, despite B18's promise that it reads the editor contents. Hold a confirmed send gesture, await a successful save acknowledgement from the host, and replay the existing composer action once, reporting a save failure before proceeding.

- **Medium, S - `bridge.js:141`:** Every non-timeout connection error retries the same request, including action tools whose response was lost after execution. A controlled upstream executed an openFile request twice after resetting the first response, contradicting the tools' Never retried contract and potentially reporting busy after an action already succeeded. Restrict automatic retries to failures proven to precede delivery, such as ECONNREFUSED, plus the existing 401 path, and return an uncertain outcome after a delivered request loses its response.

- **Medium, M - `extension.js:353`:** One B32 page's frameLoaded sets `loaded` for both pages and drains the deferred slot into `front()`, which may still be loading. In a probe where the editor frame loaded first and the side view remained visible, the deferred mention was consumed and sent only to the unready side view. Track readiness per page, retain the deferred action until its chosen page is ready, and clear that readiness when the page navigates or is rendered again.

- **Medium, M - `extension.js:491`:** The picker refresh in `threads()` bypasses `activity()`'s fetching guard, and both accept responses for the same bind without ordering them. A probe applied a completed snapshot and then let an older running snapshot restore the running state, allowing stale badges and repeated request/completion edges. Route both callers through one shared fetch or discard responses older than the latest applied fetch for that bind.

- **Medium, S - `extension.js:581`:** A request is permanently added to `answered` before ticket acquisition or sending, including failures that definitely sent no answer. A failed-response probe showed that an explicit second attempt never reached respond and instead said Already answered in T3, leaving a still-pending request misleadingly locked out for the window lifetime. Separate in-flight requests from confirmed answers, clear the in-flight entry after failure, and permit an explicit revalidated retry without automatically replaying an uncertain answer.

- **Medium, M - `panel.js:262` (also `extension.js:373`):** Navigation and mention acknowledgements carry no action ID, so a late result from one action can settle the next action. Probes showed an earlier navigation success cancelling the newer switch's fallback and a failed first mention copying the second mention into the clipboard. Add a small correlation ID to these host/panel/injected messages, accept only the matching reply from the target page, and bound the pending mention acknowledgement with its existing clipboard fallback.

- **Medium, M - `extension.js:455`:** Toast deduplication uses only a thread ID and a ten-second window, while track advances its baseline even when that window suppresses a different event. A completion within ten seconds of an earlier toast was permanently lost in a probe, and the shim can also win the race and suppress R25's richer completion text. Deduplicate by thread plus request/run event identity and assign each event one notification source so repeated polls/shim delivery are suppressed without discarding distinct events.

- **Medium, S - `extension.js:156`:** A staged addition followed by a working-tree deletion produces a vscode.changes tuple with neither an original nor a modified URI. That reproduced tuple cannot show the staged content and asks the diff viewer to render an empty pair. Use the Git index as the modified side for this staged-only case, or explicitly omit empty net-change pairs and report when no displayable changes remain.

- **Medium, S - `extension.js:669`:** With a saved session and a stale runtime file, closed-panel prebind never checks the session endpoint and treats ensureProject's non-throwing failure note as neutral status. A probe with an unreachable T3 endpoint left the status bar as T3 and started no reconnect poll, so B7/R8 work only after the panel opens. Validate server/session state before setting the closed-panel status and start the existing reconnect poll when that validation reports no answer.

- **Medium, S - `t3.js:630`:** The German-layout exception treats every Semicolon code whose key is not semicolon as the terminal shortcut. A synthetic non-US Ctrl+M event with code Semicolon was swallowed and relayed as terminal, hijacking an unrelated shortcut on layouts with that mapping. Narrow the exception to the intended O-umlaut key and leave other Semicolon mappings alone.

## 3. Nightly fragility (2 findings)

- **Medium, S - `t3.js:451`:** Switch completion depends on `data-thread-title-chevron`, but t3-facts.json has no fact for that selector even though the current ChatHeader source contains it. Removing or moving the selector will force every titled switch to time out and reload, and the existing New thread fact does not check this dependency specifically. Add the selector's ChatHeader path and exact fixed string to the fact registry with the switch fix.

- **Medium, M - `extension.js:435` (also `extension.js:41`, `extension.js:977`):** T3 notification tag/title parsing, provider request-kind literals and the T3 settings route are spread through extension.js instead of being normalized in t3.js. A nightly change to those surfaces requires coordinated host changes and can silently change which notifications or approval buttons appear, weakening the promised single T3-facing layer. Move just these T3-specific translations and route construction into t3.js and keep extension.js responsible for VS Code actions on normalized results.

## 4. Simplification (3 findings)

- **Low, S - `package.json:129`:** The menus object defines terminal/context twice, with the later definition silently shadowing the earlier one. A future edit to the first entry appears valid but has no effect, and the runtime already warns about the duplicate key. Delete the first definition and retain the later list containing both terminal actions.

- **Low, S - `panel.js:306` (also `scripts/selfcheck-panel.mjs:174`):** The host-origin busy message branch has no production sender because pairing sets busy locally and clears it through error or a new render. This unused protocol entry and its positive-only test enlarge the message contract without implementing any behavior. Remove busy from the host whitelist, branch and protocol comment, delete the redundant positive busy test, and retain the foreign-message rejection and actual pairing behavior checks.

- **Low, S - `scripts/selfcheck-panel.mjs:220`:** The popover styles, row styles and toolbar styles assertions merely copy fixed CSS values such as height 24px and top 36px. They fail on harmless layout edits while proving no interaction or security property, adding maintenance to a suite that already executes the client. Delete those three cosmetic snapshot assertions and retain the escaping/CSP, picker interaction and source/origin checks.

## Verdict

The core wrapper and authentication design are sound within the documented single-user loopback trust model, but approval context and checkout targeting need fixes before routine reliance. First preserve complete approval context and supported decisions, then resolve every action against the selected thread's root, then synchronize B32 navigation and track readiness per page. Keep the small forwarder and the existing T3 page; these fixes need no T3 modifications or replacement chat UI. The 332 offline checks and read-only live GETs passed, but they do not prove paired WebSocket approval behavior or real keyboard/drag interactions.
